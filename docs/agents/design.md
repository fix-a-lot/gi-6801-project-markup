## 디자인 참고

LOAWA를 주요 참고 사이트로 사용한다.

- 참고 사이트: https://loawa.com/
- 스크린샷: `docs/references/loawa-capture-index.jpg`
- 디자인 토큰: `docs/references/loawa-DESIGN-by-design-extractor.md`

페이지를 구현할 때 다음 순서로 참고한다.

1. 가능하면 참고 사이트를 직접 방문해 현재 화면을 확인한다.
2. 참고 사이트의 레이아웃, 정보 밀도, 시각적 계층, UI 패턴을 주요 참고 대상으로 삼는다.
3. 스크린샷은 실제 화면의 세부적인 시각 요소를 확인하기 위한 보조 자료로 사용한다.
4. 디자인 토큰은 색상, 타이포그래피, 간격, 테두리, 컴포넌트 스타일을 확인하기 위한 보조 자료로 사용한다.
5. LOAWA의 로고, 브랜드, 고유 이미지, 문구, 정확한 화면 구조를 그대로 복제하지 않고 이 프로젝트에 맞게 재해석한다.

## 디자인 원칙

- 데스크톱 우선
- 반응형 지원
- 다크 테마 중심
- 낮은 대비의 어두운 배경과 밝은 텍스트
- 제한적으로 사용하는 accent color
- 높은 정보 밀도
- 명확한 시각적 계층
- 컴팩트한 여백
- 작은 border radius
- 절제된 테두리와 그림자
- 과도한 shadow 사용 금지
- 카드 사이의 간격을 지나치게 크게 만들지 말 것
- 일반적인 SaaS 랜딩페이지처럼 여백을 과도하게 사용하지 말 것
- 정보가 많은 화면에서도 복잡해 보이지 않도록 구성할 것

## 구현 원칙

- 재사용 가능한 React 컴포넌트를 사용한다.
- 실제 API가 명시되지 않은 경우 mock 데이터를 사용한다.
- 라이트/다크 모드 전환 기능은 명시적으로 요청된 경우에만 구현한다.
- 페이지를 구성하는 기능 컴포넌트(`components/` 최상위에 위치한, 화면 한 블록을 담당하는 컴포넌트)는 최상위 요소에 `data-component="이름"` 속성을 붙인다. 브라우저 Inspect로 컴포넌트 경계와 이름을 바로 확인하기 위한 용도이며, 값은 해당 컴포넌트의 역할을 나타내는 한국어 명사로 작성한다(예: `SiteHeader` → `사이트헤더`, `WeeklySchedule` → `주간일정`).

## Responsive

- Desktop을 우선으로 디자인하되 모바일에서도 사용할 수 있어야 함

## 페이지 작업

사용자가 특정 페이지의 구현을 요청하면 해당 페이지 하나만 구현한다.

예:

> LOAWA 메인 페이지를 참고해서 메인 페이지 하나만 만들어줘.

이 경우 다음 원칙을 따른다.

- 먼저 참고 사이트의 해당 페이지를 직접 확인한다.
- 참고 사이트의 정보 구조와 UI 패턴을 분석한다.
- 프로젝트의 디자인 원칙에 맞게 독자적인 화면으로 재구성한다.
- 사용자가 요청하지 않은 페이지나 기능은 추가하지 않는다.
- 실제 데이터 연동은 요청하지 않는 한 구현하지 않는다.

## Git 작업 규칙

- 사용자가 `git pull` or `git fetch` or `브랜치 갱신`을 입력하면 원격 저장소에서 최신 정보를 갱신한다.
